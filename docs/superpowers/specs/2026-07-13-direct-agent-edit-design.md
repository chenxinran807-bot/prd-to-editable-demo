# 原型内直接 Agent 修改设计

## 目标

用户在原型中点选元素、输入自然语言要求并点击“直接修改”后，修改请求自动发送给当前 Aime 会话中的 Agent。Agent 完成修改后，当前原型自动更新；用户不需要导出 JSON、复制文件或另开 Agent，同时始终可以撤销。

## 用户流程

1. 用户进入编辑模式并点选一个原型元素。
2. 编辑面板展示元素标识、当前内容和“修改要求”。
3. 用户输入要求并点击“直接修改”。
4. 页面显示“正在修改”，禁止重复提交，但不冻结预览。
5. 当前 Aime 会话中的 Agent 收到包含原型、元素、当前状态和修改要求的结构化请求。
6. Agent 返回补丁后，页面立即应用补丁、高亮变化并记录一个历史版本。
7. 用户可点击“撤销”恢复修改前状态，也可“重做”。

按钮和文案中不再出现“保存修改任务”“导出任务”或要求用户把文件再发给 Agent 的说明。

## 宿主通信协议

页面通过一个独立的 `AgentBridge` 发送请求，业务 UI 不直接依赖 Aime 的具体实现。

请求至少包含：

- `requestId`：本次请求的唯一标识。
- `manifestId`：当前原型标识。
- `protoKey`：被选元素的稳定标识。
- `instruction`：用户输入的修改要求。
- `currentElement`：当前文案、样式、显隐、禁用和动作。
- `currentPatches`：当前原型已有补丁。
- `prototypeContext`：产品名称、当前页面、需求模型和路由信息。

响应分为：

- `accepted`：宿主已接收请求。
- `progress`：可选的处理中说明。
- `completed`：包含可直接应用的元素补丁或新原型版本地址。
- `failed`：包含可展示的失败原因和是否可重试。

首选宿主通道由 Aime 注入；Web 环境使用 `postMessage`/宿主对象适配器。页面只接受匹配 `requestId`、受信来源和当前 `manifestId` 的响应。

## 补丁与历史

Agent 返回的补丁必须经过现有字段白名单和跳转目标校验，不能执行任意脚本。补丁通过验证后作为一个原子历史版本应用：一次 Agent 修改只产生一个撤销节点，无论内部改了多少字段。

历史包含用户直接编辑与 Agent 修改，沿用统一的撤销/重做序列。刷新后的持久化行为不变。Agent 返回失败或无效补丁时不得写入历史。

## 状态与错误处理

- 空要求或未选择元素：按钮不可用。
- 提交中：显示“正在修改…”，同一元素不可重复提交。
- 成功：显示“修改完成，可撤销”，短暂高亮变化元素。
- 连接失败：原地显示“未连接到当前 Agent”，提供“重试”。
- 超时：保持用户输入，允许重试，不产生补丁。
- 无效补丁：拒绝应用并显示“Agent 返回内容未通过安全校验”。
- 宿主不支持直接通信：显示“一键复制修改指令”作为明确降级；不生成下载文件，也不伪装成已提交。

## 本地快速原型与专业原型

两类原型使用同一 `AgentBridge` 请求和响应结构。它们可以保留各自的编辑面板外观，但提交按钮、状态、错误语义、补丁校验和撤销规则必须一致。

专业原型的默认演示模式仍保持编辑 UI 隐藏和像素无损；只有进入 `?edit=1` 或快捷键唤起编辑模式后才加载直接修改交互。

## 验收标准

- 浏览器测试证明点击“直接修改”会通过模拟宿主发送一条结构化请求。
- 模拟成功响应后，页面自动应用修改并可撤销、重做。
- 刷新后已完成修改仍存在。
- 失败、超时、无效响应均不污染补丁或历史。
- 没有宿主桥时显示复制降级，不出现导出任务按钮。
- 本地快速原型和专业原型通过相同协议测试。
- 专业原型默认首屏继续与原版像素一致。
- 请求和响应不能注入脚本、未知样式或不存在的跳转目标。

## 非目标

- 不在静态 HTML 中实现或模拟大模型。
- 不创建新的 Agent 会话。
- 不要求用户管理 `agent-comments.json`。
- 不把未收到宿主成功响应的请求标记为已完成。
