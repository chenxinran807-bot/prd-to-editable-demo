# 单 Skill 最佳效果交付设计

## 目标

用户只安装 `prd-to-editable-demo` 一个 Skill，并完成一次必要授权；此后输入任意 PRD，系统自动完成需求理解、交互设计、视觉生成、Inspire 交付和质量验收。正式交付不得依赖用户另行安装 `prd-generator`、`pm-kakaxi-skills`、`figma-flow-to-html-demo`、`vne-prototype`、Open Design 或花叔 Design。

“单 Skill”指单一分发和调用入口，不代表放弃专业能力。通用且可再分发的专业方法必须内化；外部工具只在真实可用时作为增强或最终容器，不得通过名称假装已经调用。

## 产品承诺

1. 用户只安装一个包。
2. 对正式专业任务，Inspire 是最终可编辑容器。
3. 系统自动完成可以自动完成的安装、发现、预检、生成、验证和重试。
4. 只有登录、授权、不可访问素材等必须由用户完成的动作才暂停流程。
5. 未通过质量门禁的候选不得冒充正式结果；保留上一已接受版本。
6. 本地 HTML 仅用于快速评审、调试和应急预览，不作为专业模式的正式交付。

## 能力整合原则

不复制其他 Skill 的完整文件或提示词。只吸收经过验证、领域无关且可再分发的工作方法，并在本 Skill 中重新实现：

- 需求理解：用户故事、角色、目标、对象、动作、状态、规则、分支、证据、假设和缺口。
- 交互设计：任务旅程、页面职责、组件选择、状态机、异常与返回路径。
- 多输入证据：PRD、截图、Figma 流程、参考 URL、已有原型和合法素材。
- 视觉设计：移动端层级、排版、密度、间距、触控区域、Icon 和图片规范。
- 可编辑能力：文字、颜色、图片、Icon、位置、大小、显隐、状态、跳转及撤销。
- 验收能力：业务完整性、可达性、视觉专业度、素材来源、可编辑性和实际 Skill 激活情况。

单一业务案例只能进入测试集或业务设计包，不能写入通用理解协议。

## 架构

### 1. 统一入口

`SKILL.md` 只描述核心流程、质量承诺和按需读取的内部参考文件。用户不需要知道内部能力名称，也不需要手动选择专业 Skill。

### 2. 内置能力层

安装包包含四类领域无关的内部协议：

- `requirements-ir`：带原文证据的语义需求结构。
- `interaction-design`：从任务和状态推导页面、组件、反馈与流转。
- `visual-quality`：通用原生移动端视觉规则、素材与反模式。
- `quality-gates`：确定性检查与主观设计审查的准出标准。

这些协议构成完整基础能力，不能要求宿主已安装其他同类 Skill。

### 3. 执行能力层

- 本地运行时负责结构校验、快速预览、可编辑运行时和确定性验收。
- Inspire CLI 负责专业候选生成和最终可编辑容器。
- Inspire 业务设计 Skill 以随包发布或可解析配置的方式提供；运行时必须校验其来源、版本、package hash、opened 和 activated 记录。
- 不把外部 Skill 名称视为能力。只有宿主真实发现并可调用时，才能作为可选增强输入。

### 4. 质量保障控制器

控制器维护 `preflight → understand → design → generate → audit → accept` 状态：

- 可自动修复：自动安装可安装组件、重新解析可见 Skill、重新生成候选、修复确定性错误。
- 必须用户参与：登录、账号授权、受限资源访问和会改变核心方案的关键选择。
- 素材缺失：生成专业通用占位素材并标记待替换；不得使用 Emoji、文字假 Icon 或无来源品牌资产。
- 验收失败：保留上一已接受版本并自动迭代；达到重试上限后报告具体失败证据，不交付失败候选。

## 数据流

1. 读取完整 PRD 和用户提供的证据。
2. 宿主模型生成 `model-semantic` IR；程序校验原文证据、对象、动作和流转端点。
3. 交互设计协议生成页面职责、状态矩阵、组件与完整任务旅程。
4. 视觉协议根据产品类型、平台、参考证据和可用素材形成设计约束。
5. 预检 Inspire 登录、CLI、业务设计 Skill 可见性与版本完整性。
6. Inspire 生成新候选，返回 assetId、预览、收纳箱链接和 Skill trace。
7. 确定性验收检查业务覆盖、可达性、状态、素材、编辑能力和 Skill 激活。
8. 主观审查检查视觉层级、原生感、业务语义、素材质量和演示价值。
9. 通过后提升为已接受版本；失败则从审查证据生成定向修订并再次生成。

## 正式模式与快速模式

### 专业模式

用户要求高保真、品牌感、原生移动体验或 Inspire 编辑时自动启用。Inspire 和质量验收是硬门禁；不得静默降级成通用本地页面。

### 快速评审模式

用户明确优先速度、只需可演示初版时可生成本地可交互 HTML。它仍必须使用语义 IR、完整主流程和可编辑运行时，并明确标记不是正式专业交付。用户可以随时升级到专业模式。

## 用户交互

默认不要求用户理解环境配置。状态以产品语言呈现：

- “正在理解需求”
- “正在准备专业设计能力”
- “需要你完成一次 Inspire 授权，完成后自动继续”
- “正在检查业务流程和视觉质量”
- “第一版未达到交付标准，正在自动优化”
- “原型已生成，可在 Inspire 中继续编辑”

任何暂停都必须说明为什么需要用户、完成后会发生什么，并支持从原状态继续。

## 错误与降级

- Inspire 未登录：请求一次授权，授权后自动续跑。
- CLI 缺失但允许安装：自动安装并复检；不能安装时给出单步操作。
- 指定业务设计 Skill 不可见：重新解析随包配置和当前账号可见列表；仍不可见则暂停正式模式，不使用 built-in 冒充。
- PRD 证据不足：低代价推断写入 assumptions；会推翻核心流程的问题只问一个关键问题。
- 品牌素材缺失：使用合规通用素材并标注替换点，不宣称品牌一致。
- 多次生成未达标：交付失败报告和最后一个可预览候选，但候选状态保持 review-required。

## 验收标准

### 单包独立性

- 在没有安装任何同类专业 Skill 的干净宿主中，可完成语义建模、快速 Demo 和质量检查。
- `SKILL.md` 不把外部 Skill 名称写成强制依赖。
- 安装包包含所有被核心流程引用的协议、脚本、运行时和通用素材。

### 专业交付

- Inspire 实际 opened 和 activated 的 Skill 与预检解析结果完全一致。
- 核心用户旅程从入口到结果可达，必要异常和返回路径可用。
- PRD 业务对象、动作、状态和规则均有页面或交互证据。
- Emoji 为 0；Icon、图片和品牌素材都有来源或明确的待替换状态。
- 文字、颜色、图片、Icon、位置、大小、显隐、状态和跳转可以继续编辑并支持撤销。
- 自动检查通过后仍需主观视觉审查；不得把规则通过等同于设计优秀。

### 泛化与对抗测试

- 使用至少三个互不相关且词表未知的 PRD 验证理解和生成。
- 使用文档章节很多但页面很少的 PRD，验证不会把章节机械变成页面。
- 使用缺少异常状态的 PRD，验证系统会标记缺口而非伪造事实。
- 模拟 Inspire 回退到 built-in Skill，验证正式交付被拒绝。
- 模拟外部专业 Skill 全部缺失，验证基础闭环仍可运行。

## 非目标

- 不承诺凭一个安装包获得用户账号本来没有的 Inspire 权限。
- 不再分发未经授权的第三方 Skill、私有品牌素材或设计文件。
- 不把快速评审 HTML 宣称为品牌级最终原型。
- 不把任何单一 PRD 的页面和状态硬编码为通用能力。
