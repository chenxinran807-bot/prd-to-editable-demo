# Figma 驱动的 Inspire 业务设计 Skill 方案

## 目标

以抖音电商真实 Figma 文件为可追溯设计源，提升 `douyin-mall-independent-app-prototype-guidance` 对独立端 App 的原生视觉、组件组合和业务状态理解，同时避免把单个项目的临时样式固化为全局规则。

## 已验证输入

- Figma 组织：ByteDance Design / 抖音电商设计。
- 重点团队：导购用户体验-独立端、导购用户体验-商城频道、通用组件。
- 首个样本：`激励改版`，file key `H2hzy9QGoK31fNWOtLg3Gd`。
- 已确认可读取内容：页面、移动端画板、节点结构、组件实例、业务文案、评审评论与画板截图。
- 当前权限：View seat。结构读取与截图可用；`use_figma` 脚本遍历因 Full seat 限制不可用。

## 知识分层

### 1. 来源证据层

每个样本记录 Figma 文件、页面、节点 ID、截图哈希、读取日期和适用范围。截图只作为审查证据，不直接打包进公开 Skill；涉及内部设计的文件不得外传或公开发布。

### 2. 稳定设计规则层

只有跨多个画板或多个项目重复出现的规律才能进入全局规则，包括：

- 375/390px 移动端内容画布与安全区；
- 原生状态栏、顶部导航、内容区和底部导航的层级；
- 8px 级页面边距、双列商品流、任务卡和主要按钮的密度关系；
- 利益数字、行动按钮、辅助文案和状态反馈的优先级；
- 真实图标、图片素材与组件实例优先，禁止 Emoji 和文本伪图标。

### 3. 场景模式层

激励、金币、导流、大促、搜索和商城频道分别记录为场景模式。模式描述业务对象、必要状态、组件组合和不应泛化的视觉资产，不将活动主题色或一次性营销素材提升为全局 Token。

### 4. 阻断规则层

以下情况阻止宣称“抖音商城原生设计”：

- 无 Figma/官方素材来源却声称使用品牌资产；
- 把单个营销项目的橙黄渐变应用到所有商城页面；
- 使用桌面侧栏、假手机框、Emoji 或通用 AI 紫色渐变；
- 缺失 PRD 必要动作、处理中、成功、失败或回流状态；
- 业务设计 Skill 未在 Inspire 中真正 activated/opened。

## Product Design 插件定位

采用“辅助审查，不做最终容器”的方式：

- `audit`：对 Figma 样本和 Inspire 候选截图做 UX、视觉、可访问性审查；这是当前最有价值的能力。
- `ideate`：仅在需要探索新方向且没有官方目标画板时使用，不能替代已有原生设计源。
- `image-to-code`：仅在选定具体 Figma 画板并需要忠实还原时使用。
- `url-to-code`、`share`：不进入本轮主链路，避免与 Inspire 最终容器重复。

## 数据流

```text
Figma 目录
  → 选择代表项目和画板
  → 结构与截图证据
  → 通用规则 / 场景模式 / 特例分层
  → Inspire 业务设计 Skill
  → 新 PRD 候选原型
  → Product Design 截图审查 + 现有确定性门禁
  → 通过后发布新版本
```

## 第一轮实施范围

1. 建立 Figma 来源清单和证据目录。
2. 从 `激励改版` 提炼移动画布、利益表达、任务卡、商品流和状态层级。
3. 更新 Skill 的 references、components、negative rules 和来源清单。
4. 不复制评论、成员信息和不必要的内部素材。
5. 选择未参与提炼的独立端画板作为对抗测试。
6. 通过结构测试、Skill 行为测试、Inspire 激活检查和截图审查后再发布候选版本。

## 验收标准

- 每条新增规则都能追溯到至少一个 Figma 节点；全局规则需要至少两个独立样本支持。
- 新 Skill 不把激励项目的活动视觉错误泛化到非激励 PRD。
- 生成结果不出现 Emoji、假手机框、桌面布局或无来源品牌资产。
- 候选必须覆盖 PRD 的关键动作和状态。
- Product Design 插件的结论必须绑定当前轮截图，不以记忆或旧结果代替证据。
- 当前 View seat 限制被显式记录，流程不依赖 Full seat 才能完成。

## 非目标

- 批量复制整个抖音电商 Figma 目录。
- 把内部设计文件或截图发布到公开 Skill。
- 用 Product Design 插件取代 Inspire、Figma 或外部编排 Skill。
- 在缺少多源证据时宣称已经形成完整官方设计系统。
